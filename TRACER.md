- **Data source research (verified with real requests, not assumptions):** the resource [`9ef84268-d588-465a-a308-a864a43d0070`](https://www.data.gov.in/resource/9ef84268-d588-465a-a308-a864a43d0070) — *Current Daily Price of Various Commodities from Various Markets (Mandi)* — published by the **Ministry of Agriculture and Farmers Welfare** (Directorate of Marketing and Inspection) on `data.gov.in`, and published under the **Government Open Data Licence - India** (confirmed on the official resource page). - **Verified upstream behaviour** (each confirmed by an actual HTTP request): an `api-key` is **required** — a request without one is rejected with `400`, an unknown key with `403`; `filters[state]`, `filters[district]`, `filters[market]` and `filters[commodity]` are honoured and match case-insensitively; **there is no usable date filter**, so dates are applied to the fetched page instead; every response is **capped at 10 records** whatever `limit` asks for; the service advertises **no request budget** in its headers (`X-Ratelimit-Limit: -1`), but measured behaviour is a burst budget of roughly 25 requests in a short window, after which it answers `429`; the resource publishes **no coordinates**, so the API never reports a distance for a live market.
- **Live provider (`backend/src/lib/providers/dataGovInProvider.ts`):** pages through the capped 10-record resource, normalises every record, and **never fabricates**. A failed page is retried (default 3 extra attempts) with a longer backoff when the upstream answers `429`; a dropped connection is retried sooner; a rejected key is **not** retried. Pages are cached for 5 minutes, upstream calls are spaced at least 250 ms apart, and at most 3 upstream pages are read per request, so the provider stays inside the measured budget. Records fetched during the request are `LIVE`; records served from the cache are `RECENT`. An unusable upstream record (missing field, unparseable date, negative price, minimum above maximum) is **dropped and counted**, never repaired.
- **Demo provider (`backend/src/lib/providers/demoProvider.ts`):** reads the **already seeded** PostgreSQL rows through the existing repositories and generates nothing at request time, so repeated requests are identical and the API never writes to the database. A stored row whose status is not `DEMO` or whose source is not `demo-seed` is **skipped**, so a demo request can never serve a live row and vice versa.
- **Provider selection (`backend/src/lib/providers/registry.ts`):** `MANDI_DATA_PROVIDER_MODE` picks `demo` or `live`. An **unknown mode is rejected** with a clear error rather than silently falling back to demo data.
- **Endpoints added:** `GET /api/mandi-prices` (filters `crop`, `market`, `state`, `district`, `from`, `to`, `limit` 1-100 default 25, `offset` 0-10000), `GET /api/markets` (filters `market`, `state`, `district`, `limit`, `offset`), and `GET /api/data-sources` (which provider is configured, whether it is demo or verified-live, and — in live mode — the result of **one real probe request**). Each price and market response carries a `dataSource` block naming the provider, its mode, its status, a plain-language notice, the source URL, and the attribution.
- **Labelling is enforced at the API boundary, not just in the data:** every observation carries its own `dataStatus` and `source`, and `isLive` is true only for a `LIVE` record. A provider that cannot run is reported as `dataStatus: "UNAVAILABLE"` with `label: "Unavailable"` and `isLiveData: false`.
